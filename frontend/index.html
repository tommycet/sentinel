§i — architecture

One signal path. No hidden hops.

ALERT (SigNoz webhook) → HMAC VERIFY → SQLITE (IncidentStore) → LINEAGE QUERY → REVOKER (vault / DB / API) → OTLP EXPORT

§ii — capabilities

Every agent artifact. Every dependency. One revocation surface.

01 — AgentLineage

Trace every run back to the brain capture.

Each incident links to the original hermes-brain-capture artifact, the LLM response, vault read, DB mutation, and external API call — in sequence. No orphans. Query by incident ID or model provider.

  • hermes-brain-capture (LLM artifact)
  • vault-access (credential read revocable)
  • db-mutation (SQLite + OTLP trace)
  • api-external (revocable token scope)
  • cost-tracking (per-call cost + aggregate)

02 — Cross-Agent Lineage

Detect cross-agent contamination.

If agent A's vault read leaks into agent B's prompt, the lineage graph flags the shared credential.id_hash and raises a cross-agent audit event automatically. No manual correlation.

03 — Revocation

One endpoint kills the full blast radius.

A single POST /revoke call revokes the vault key, kills the DB session, cancels the external API token, and writes an OTLP span — in sequence. Each revocation is confirmed with a revoked=true line in the audit log before the endpoint returns 204.

Quick Start

Sentinel requires Python 3.10+ and zero external dependencies. Install from source:

# Clone the repository
git clone https://github.com/sigaz/sentinel.git
cd sentinel

# Install (editable mode)
pip install -e .

# Or run directly
python -m sentinel --port 8090 --webhook-secret YOUR_SECRET

Environment Variables

SENTINEL_PORT=8090              # HTTP server port
SENTINEL_HOST=0.0.0.0           # Bind address
SENTINEL_WEBHOOK_SECRET=...     # HMAC secret for SigNoz alerts
SENTINEL_DB_PATH=./sentinel.db  # SQLite database path
SENTINEL_DRY_RUN=false          # Preview mode (no revocation)
SENTINEL_OTEL_ENDPOINT=http://localhost:4317  # OTLP trace export

Verify Installation

curl -s http://localhost:8090/health
# → {"status": "ok", "version": "0.1.0"}

Provider Configuration

Sentinel supports multiple LLM providers globally. Configure via environment or the config file:

# 9router (default gateway)
NINE_ROUTER_URL=http://127.0.0.1:20128/v1

# Groq (free tier, fast inference)
GROQ_API_KEY=gsk_...
GROQ_MODEL=llama-3.3-70b-versatile

# OpenRouter (27+ free models)
OPENROUTER_API_KEY=sk-or-...
OPENROUTER_MODEL=meta-llama/llama-3.3-70b-versatile

Provider Priority

  • 9router — primary gateway, routes to 40+ upstream providers
  • Groq — fastest inference, free tier available
  • OpenRouter — widest model selection, free tier: 200 req/day

Fallback Chain

Sentinel automatically falls back to the next provider if the primary fails. Configure the fallback order in config.json:

{
  "providers": {
    "primary": "9router",
    "fallback": ["groq", "openrouter"],
    "timeout_ms": 30000,
    "max_retries": 2
  }
}

SigNoz Alert Webhook

Sentinel receives alerts from SigNoz via signed webhooks. The alert payload follows the SigNoz alert format:

{
  "alert": {
    "name": "AgentRunaway",
    "severity": "critical",
    "description": "Agent exceeded resource limits"
  },
  "incident": {
    "agent_id": "hermes-brain-capture",
    "run_id": "run_abc123",
    "model": "llama-3.3-70b-versatile",
    "tokens_used": 12847,
    "timestamp": "2026-07-26T10:30:00Z"
  }
}

HMAC Verification

Every request must include the HMAC signature headers:

X-Sentinel-Timestamp: 1721984400
X-Sentinel-Signature: sha256=a1b2c3d4e5f6...

The signature is computed as HMAC-SHA256(webhook_secret, timestamp + "." + body).

Revocation API

Kill the full blast radius of a runaway agent with a single call:

# Revoke an incident's credentials
POST /incidents/{id}/release

# Request body
{
  "reason": "Agent exceeded resource limits",
  "revoke_vault": true,
  "revoke_db_session": true,
  "revoke_api_tokens": true
}

# Response (204 No Content)
{
  "incident_id": "incident_001",
  "revoked": true,
  "vault_revoked": true,
  "db_session_killed": true,
  "api_tokens_revoked": true,
  "otlp_span_exported": true,
  "audit_log": "revoked=true; revoked_at=2026-07-26T10:30:05Z"
}

Dry Run Mode

Test revocation without actually killing credentials:

# Start in dry-run mode
python -m sentinel --dry-run --webhook-secret SECRET

# Revocation will return 204 but not actually revoke
# Audit log shows "dry_run=true"

System Architecture

Sentinel follows a minimal, stdlib-only design. Every component is a single Python file with zero external dependencies.

Component Map

sentinel/
├── __main__.py       # CLI entry point
├── app.py            # HTTP server (BaseHTTPRequestHandler)
├── auth.py           # HMAC-SHA256 webhook verification
├── model.py          # Incident data model + SigNoz parser
├── store.py          # SQLite incident store (sql.js fallback)
├── revoker.py        # Credential revocation orchestrator
├── lineage.py        # AgentLineage graph builder + query
└── telemetry.py      # OTLP/HTTP trace export

Request Flow

  • Ingress — SigNoz sends signed webhook to /alerts
  • Verify — HMAC-SHA256 check + replay guard (301s TTL)
  • Parse — Extract incident, agent, model, tokens from payload
  • Store — Write to SQLite + build AgentLineage graph
  • Query — GET /agent-lineage returns linked artifacts
  • Revoke — POST /incidents/{id}/release kills blast radius
  • Export — OTLP span sent to SigNoz collector

Data Flow Diagram

SigNoz Alert → HMAC verify → Parse → SQLite → Lineage → OTLP export
                    ↓
              Revoke → vault / DB / API → 204 OK

Troubleshooting

Common Issues

  • "Invalid or expired signature" — Check that SENTINEL_WEBHOOK_SECRET matches the SigNoz alert webhook secret. The timestamp must be within 301 seconds.
  • "Body too large" — Sentinel rejects payloads > 64 KiB. Check SigNoz alert payload size.
  • "No SQLite driver" — Copy sql-wasm.wasm to the standalone bundle: cp node_modules/sql.js/dist/sql-wasm.wasm .next/standalone/node_modules/sql.js/dist/
  • "Connection refused" on OTLP — Ensure the SigNoz collector is running on localhost:4317. Sentinel continues without telemetry on failure.
  • Groq 404 errors — Verify the model ID is available: curl -s https://api.groq.com/openai/v1/models | jq '.data[].id'

Diagnostic Commands

# Check server health
curl -s http://localhost:8090/health

# View recent incidents
curl -s http://localhost:8090/agent-lineage | python -m json.tool

# Test Groq connection
curl -s https://api.groq.com/openai/v1/models \
  -H "Authorization: Bearer $GROQ_API_KEY" | jq '.data[].id' | head -5

# Verify HMAC signature
echo -n "TIMESTAMP.BODY" | openssl dgst -sha256 -hmac "$SECRET"

Performance Tuning

  • SQLite WAL mode is enabled by default for concurrent reads
  • OTLP export timeout: 5s (configurable via SENTINEL_OTEL_TIMEOUT)
  • Replay guard TTL: 301s (configurable in app.py)
  • Max request body: 64 KiB (configurable in app.py)
