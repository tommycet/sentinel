# Building a Circuit Breaker for AI Agents Using Only Observability

## The Problem

One of our AI agents got stuck in an infinite tool-call loop during a demo. It wasn't a code bug — it was a prompt misconfiguration that caused the agent to retry the same MCP tool with the exact same arguments eight times per second. The credentials were API-scoped, so there was no blast radius, but the event logs were useless: by the time we noticed, the agent had burned through 200k tokens and the demo was over.

We had observability. We could *see* the loop in SigNoz. But seeing wasn't stopping.

## The Idea

What if the observability platform *was* the enforcement mechanism? What if, instead of alerting a human who then SSH's into a box to revoke a key, the alert webhook itself triggers an automated, reversible quarantine?

That's Sentinel.

## How It Works

SigNoz collects OpenTelemetry spans from every agent tool call. When the same (tool, arg_hash) pair repeats ≥8 times in 60 seconds, SigNoz fires an alert webhook. The webhook is HMAC-signed with replay protection. Sentinel receives it, parses the alert payload, computes an idempotency key, checks its SQLite store for duplicates, then calls a revoker adapter (dry-run by default) to quarantine the credential. Every step emits OTLP spans back to SigNoz — the circuit breaker observes itself.

```python
# src/sentinel/auth.py — HMAC verification, 30 lines
def verify_webhook(timestamp, signature, body, secret):
    signed = f"{timestamp}.".encode() + body
    expected = hmac.new(secret.encode(), signed, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```

## Takeaways

**What worked:** The idempotency-gated store was the right call. During testing, duplicate webhooks arrived in bursts (SigNoz retries), and the SQLite `BEGIN IMMEDIATE` + unique constraint pattern handled them perfectly — exactly one action per incident.

**What surprised us:** The hardest part wasn't the quarantine logic — it was the telemetry export. Emitting valid OTLP/HTTP JSON by hand (without the OpenTelemetry SDK) required careful reading of the spec. The `credential.id` attribute must be SHA-256 hashed to avoid leaking secrets into traces.

**What I'd tell my past self:** Start with the JSON schema of the alert webhook. The SigNoz payload has nested `labels` and optional `fingerprint` fields that determine the idempotency key computation. Parse first, code second.
